# خريطة الملفات: اسم كل كود، وظيفته، ومكان استخدامه

## أولًا: أين يُشغّل كل نوع من الأكواد؟

| نوع الملف | المسار | أين يُستخدم أو يُلصق؟ | هل يحتاج استضافة مستقلة؟ |
|---|---|---|---|
| HTML | `frontend/index.html` | هيكل صفحات الموقع؛ المتصفح يحمّله من Cloudflare Pages | نعم، ضمن ملفات الواجهة المنشورة |
| CSS | `frontend/assets/css/*.css` | تصميم الألوان والخطوط والحركة والتخطيط؛ تُحمّل من `index.html` | نعم، ضمن ملفات الواجهة المنشورة |
| JavaScript للمتصفح | `frontend/assets/js/*.js` | منطق الواجهة واتصال Supabase؛ يعمل داخل متصفح المستخدم | نعم، ضمن ملفات الواجهة المنشورة |
| JSON | `frontend/translations/*.json` | ملفات نصوص مرجعية للغات؛ حاليًا لا تُطبّق الترجمة الكاملة تلقائيًا | تُرفع مع الواجهة، لكنها لا تكفي وحدها لتفعيل الترجمة |
| SQL | `supabase/migrations/001_schema.sql` | يُنسخ كاملًا إلى Supabase Dashboard → SQL Editor ويُشغّل على قاعدة البيانات | لا يُرفع إلى Cloudflare ليعمل؛ يُنفّذ داخل Supabase |
| إعداد Cloudflare Pages | `frontend/_headers` | يقرأه Cloudflare Pages من جذر مجلد الملفات المنشورة | يُرفع مع الواجهة ويجب أن يكون بجوار `index.html` في ناتج النشر |
| إعداد GitHub Actions الاختياري | `ops/keep_alive.example.yml` | إذا قررت استخدامه، انسخه إلى `.github/workflows/keep_alive.yml` في جذر مستودع GitHub | ينفّذه GitHub Actions؛ لا يحتاج تشغيلًا على Cloudflare |
| أمثلة مرجعية | `reference-snippets/*` | للمقارنة مع مقتطفات المواصفات فقط | لا تُستبدل بها ملفات التشغيل، ولا يُشغّل SQL المرجعي |

## ثالثًا: التشغيل المحلي على Mac

1. فك الضغط وافتح مجلد `Time-Management-System-Starter` في محرر مثل VS Code.
2. جهّز Supabase وشغّل ملف SQL الصحيح كما سبق.
3. افتح `frontend/assets/js/config.js` وضع رابط المشروع ومفتاح Publishable الصحيحين.
4. افتح Terminal وشغّل:

```bash
cd /المسار/إلى/Time-Management-System-Starter/frontend
python3 -m http.server 8000
```

5. افتح `http://localhost:8000` في المتصفح. لا تفتح `index.html` بالنقر المزدوج؛ التشغيل عبر خادم محلي أفضل، خصوصًا للميزات التي تحتاج سياقًا آمنًا مثل الميكروفون.

## رابعًا: أين تنشر الأكواد؟

### قاعدة البيانات والدخول والتخزين — Supabase

الموقع الرسمي: https://supabase.com/

- SQL: `supabase/migrations/001_schema.sql` في **SQL Editor**.
- الحسابات: **Authentication → Users**.
- إعدادات الاتصال: من لوحة المشروع، انسخ **Project URL** و**Publishable key** إلى `frontend/assets/js/config.js`.
- التخزين: الـ SQL ينشئ حاويتي `audio-notes` و`ticket-attachments` الخاصتين.
- لا تضع المفتاح السري `sb_secret_...` أو مفتاح `service_role` في ملفات الواجهة، ولا تنشره في GitHub. المفتاح الموجود في المتصفح يجب أن يكون Publishable وتُفرض الصلاحيات عبر RLS.

### ملفات الموقع — Cloudflare Pages

الموقع الرسمي: https://pages.cloudflare.com/

الطريقة المباشرة المقترحة:

1. أنشئ مستودع GitHub جديدًا: https://github.com/.
2. فك ضغط الحزمة وانسخ **محتويات مجلد** `Time-Management-System-Starter` إلى جذر المستودع (أي اجعل `frontend` و`supabase` و`docs` مجلدات مباشرة في جذر المستودع، لا ترفع ملف ZIP وحده).
3. اربط المستودع بـ Cloudflare Pages.
4. لأنه موقع HTML/CSS/JavaScript ثابت، لا يحتاج أمر بناء في هذا الإصدار. اجعل مجلد الملفات المنشورة/Build output directory هو `frontend`، واترك Root directory فارغًا عند رفع محتويات المشروع إلى جذر المستودع.
5. تأكد أن `frontend/index.html` و`frontend/_headers` يظهران في ناتج النشر بجوار بعضهما، ثم افتح الرابط واختبر الدخول.

**من الذي يستضيف ماذا؟** GitHub يحفظ ملفات المصدر ويطلق النشر عند الربط، وCloudflare Pages يستضيف واجهة الموقع، وSupabase يستضيف قاعدة البيانات والمصادقة والتخزين. لا يلزم لصق أكواد CSS أو JavaScript في لوحة Supabase، ولا يلزم لصق SQL في Cloudflare.

## خامسًا: إعداد حساب المسؤول

بعد تشغيل ملف SQL وإنشاء حسابات الدخول من **Authentication → Users**، افتح SQL Editor ونفّذ الأمر التالي مع استبدال النص بالـ UUID الحقيقي لحساب المسؤول فقط:

```sql
update public.profiles
set role = 'ADMIN'
where id = 'ضع-هنا-UUID-حساب-المسؤول';
```

اترك حساب المستفيد على الدور `USER`. لا تعِد تسمية الأدوار ولا تُنشئ جدولًا يدويًا لكلمات المرور؛ Supabase Auth هو المسؤول عنها.

## سادسًا: ملاحظات مهمة قبل النشر

- ملف `config.js` في الحزمة يحتوي قيمًا نائبة؛ الموقع لن يتصل بقاعدة البيانات حتى تستبدلها بقيم مشروعك.
- لا تشغّل `reference-snippets/schema_excerpt_original.sql`.
- لا ترفع مجلد `reference-snippets` بدل ملفات التشغيل ولا تستبدل الملفات العاملة بالمقتطفات.
- ملف `ops/keep_alive.example.yml` اختياري ولا يضمن منع إيقاف المشروع الخامل؛ راقب لوحة Supabase ورسائل البريد. راجع السياسة الحالية: https://supabase.com/docs/guides/platform/free-project-pausing
- تفاصيل الباقات المجانية قد تتغير؛ راجع صفحات الأسعار والحدود الرسمية قبل اعتماد المشروع على سعة محددة.
