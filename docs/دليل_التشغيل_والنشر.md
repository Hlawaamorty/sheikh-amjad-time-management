# دليل تشغيل ونشر منظومة إدارة الوقت والمهام

## ما الذي تستلمه؟

هذه حزمة بداية منظمة مبنية على المواصفات المرسلة، وليست استخراجًا من مستودع برمجي سابق؛ رسالتك احتوت وثيقة مواصفات ومقتطفات كود، لا جميع ملفات الموقع الفعلية. لذلك فصلتُ **المقتطفات المرجعية** التي لا ينبغي تعديلها عن **نسخة بداية تشغيل** أنشئت لاستكمال الأجزاء الناقصة. التصميم الحالي جديد ومبسّط ولا يدّعي أنه يعيد إنتاج لقطات شاشة سابقة أو جميع التفاصيل الواردة في وصف الواجهات.

## محتويات الحزمة

- `frontend/index.html`: هيكل الواجهة.
- `frontend/assets/css/design-tokens.css`: ألوان الوضعين الداكن والفاتح.
- `frontend/assets/css/typography.css`: مستويات الخط الستة.
- `frontend/assets/css/animations.css`: احترام تفضيل تقليل الحركة.
- `frontend/assets/css/app.css`: تخطيط الصفحة والتجاوب مع الهاتف.
- `frontend/assets/js/config.js`: مكان إعداد رابط Supabase ومفتاح العميل العام.
- `frontend/assets/js/app.js`: تسجيل الدخول، مهام اليوم وحالاتها، الملاحظات الخاصة، التسجيل الصوتي، المراجعة الأسبوعية، التذاكر والمرفقات، إعدادات المستخدم ولوحة المسؤول الأولية.
- `frontend/translations/`: مفاتيح ونصوص مرجعية للغات المطلوبة؛ لم يتم بعد تعميم الترجمة على كل عناصر الواجهة.
- `supabase/migrations/001_schema.sql`: الجداول وسياسات RLS والتخزين.
- `reference-snippets/`: مقتطفات من الأكواد التي أرسلتها، محفوظة للمراجعة.
- `ops/keep_alive.example.yml`: مثال اختياري للنبضة، ولا يضمن منع إيقاف مشروع Supabase.

## المرحلة الأولى: إنشاء Supabase

1. افتح `https://supabase.com/` وأنشئ مشروعًا جديدًا. الخطة المجانية مناسبة للتجربة، لكن قد يُوقَف المشروع إذا ظل نشاط قاعدة البيانات منخفضًا نحو أسبوع؛ راجع التنبيه والحدود الحالية في لوحة Supabase.
2. افتح مشروعك ثم **SQL Editor**.
3. افتح الملف `supabase/migrations/001_schema.sql` في VS Code، وانسخ محتوياته كاملة إلى SQL Editor ثم اضغط **Run**. نفّذه على مشروع جديد لتجنب تعارض أسماء الجداول/السياسات.
4. من **Project Settings → API** انسخ **Project URL** و**anon/publishable key**.
5. افتح `frontend/assets/js/config.js` وبدّل القيمتين:
   - `https://YOUR-PROJECT-REF.supabase.co`
   - `YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY`
   لا تضع `service_role` أو أي مفتاح سري داخل ملفات الواجهة أو GitHub.

## المرحلة الثانية: إنشاء حساب المسؤول والمستفيد

1. من Supabase افتح **Authentication → Users → Add user**.
2. أنشئ حسابًا للبريد الإلكتروني وكلمة المرور للمسؤول. كرر ذلك لإنشاء حساب المستفيد.
3. بعد إنشاء كل مستخدم، ابحث عن `id` الخاص به في جدول Authentication Users.
4. افتح **SQL Editor** وشغّل الأمر التالي مع استبدال UUID بالمعرّف الحقيقي لحساب المسؤول فقط:

```sql
update public.profiles
set role = 'ADMIN'
where id = 'ضع-هنا-UUID-حساب-المسؤول';
```

5. تأكد أن حساب المستفيد دوره `USER`:

```sql
select id, username, role from public.profiles order by created_at;
```

لا تسمح للمستخدم العادي بتعديل `role`، ولا تُضف زر تسجيل ذاتي مفتوحًا قبل تصميم تدفق آمن لإدارة الحسابات.

## المرحلة الثالثة: تشغيل محلي على MacBook Pro

1. فك ضغط ملف ZIP وافتح مجلد `Time-Management-System-Starter` في VS Code.
2. عدّل `frontend/assets/js/config.js` كما سبق.
3. من VS Code ثبّت إضافة Live Server أو استخدم Python المتاح في macOS، ثم شغّل خادمًا محليًا من مجلد `frontend`:

```bash
cd frontend
python3 -m http.server 8000
```

4. افتح `http://localhost:8000` في المتصفح. التسجيل الصوتي يتطلب سياقًا آمنًا؛ `localhost` وHTTPS مناسبان عادةً.
5. سجّل الدخول بحساب المستفيد أو المسؤول الذي أنشأته في Supabase.

## المرحلة الرابعة: النشر المجاني على GitHub وCloudflare Pages

1. أنشئ مستودع GitHub جديدًا. ارفع **محتويات مجلد `frontend` فقط** إلى جذر المستودع إذا كنت ستستخدم إعدادات Cloudflare أدناه، أو ارفع الحزمة كاملة ثم اجعل Build output directory هو `frontend`.
2. افتح Cloudflare Dashboard → **Workers & Pages / Pages** ثم أنشئ مشروع Pages مربوطًا بمستودع GitHub.
3. مشروع HTML/CSS/JS ثابت لا يحتاج عملية build: اختر إعداد **None** أو أمر بناء فارغ بحسب واجهة Cloudflare الحالية، وحدد مجلد الإخراج الذي يحتوي على `index.html` (مثل `frontend` إذا رفعت جذر الحزمة).
4. بعد النشر افتح الرابط المنشور وجرب تسجيل الدخول. لا تحتاج إلى وضع مفتاح Supabase سري في إعدادات Cloudflare؛ مفتاح anon/publishable موجود في `config.js` ومصمم للاستخدام العام، أما الأمان فيفرضه RLS.
5. كل تحديث ترفعه إلى GitHub سيطلق نشرًا جديدًا تلقائيًا إذا كان التكامل مضبوطًا.

روابط المنصات الرسمية:
- Supabase: https://supabase.com/
- Cloudflare Pages: https://pages.cloudflare.com/
- GitHub: https://github.com/
- وثائق إيقاف مشاريع Supabase الخاملة: https://supabase.com/docs/guides/platform/free-project-pausing

## كيف تعمل الملفات الخاصة؟

- `private_task_notes` منفصل عن جدول `tasks`، ولا توجد له سياسة قراءة للمسؤول.
- `weekly_reviews` و`audio_notes` مقيّدان بمالك الحساب ولا توجد سياسات تسمح للمسؤول بقراءتهما من واجهة العميل.
- حالات الإنجاز مخزنة في `task_progress`، ويمكن للمسؤول قراءتها لحساب الإحصاءات.
- رسائل ومرفقات التواصل قابلة للقراءة للمستفيد صاحب التذكرة وللمسؤول وفق RLS.
- كلمات المرور يديرها Supabase Auth؛ لا تُخزَّن في جدول يدوي ولا تُقرأ من لوحة الموقع.

هذه السياسات أفضل من محاولة إخفاء عمود `personal_notes` داخل صف يستطيع المسؤول قراءته؛ RLS يتحكم في الصفوف ولا يحجب أعمدة بعينها. فصل المعلومات الخاصة هو الأساس هنا.

## ما الذي لم يكتمل بعد؟

هذه حزمة أولى عملية وليست إصدارًا إنتاجيًا نهائيًا. يلزم قبل الاعتماد الكامل:

- مراجعة قواعد الأمان واختبارها بحسابين مختلفين، خصوصًا منع الوصول لمعرفات مستخدمين آخرين.
- استكمال ترجمة كل نصوص الواجهة للإنجليزية والعامية المصرية؛ ملفات الترجمة الحالية مرجعية فقط.
- إضافة شاشة إدارة أكثر اكتمالًا لتعديل المهام وإعادة ترتيبها وتعديل رسالة الجمعة والفترات.
- دعم تحرير وقت المهمة للمستفيد إذا كان `is_time_editable` مفعّلًا؛ يوجد الحقل في قاعدة البيانات لكن واجهة التحرير لم تُنفذ هنا.
- إضافة اختبارات تلقائية وحماية إضافية للملفات وحدود حجم/نوع المرفقات بحسب حاجة المشروع.
- إجراء اختبار فعلي بعد إدخال بيانات مشروعك؛ لم أستطع اختبار الحزمة على مشروع Supabase مرتبط بحسابك.

## استكشاف الأخطاء

**رسالة إعداد config.js:** تأكد أن رابط المشروع والمفتاح العام صحيحان، وأنك لم تترك النصوص الافتراضية.

**لا يظهر ملف المستخدم بعد الدخول:** أنشئ المستخدم بعد تشغيل SQL؛ المشغّل ينشئ صفًا تلقائيًا في `profiles`. إذا كان الحساب قد أُنشئ قبل تشغيل المشغّل، أضف صف الملف الشخصي أو أعد إنشاء الحساب.

**المسؤول لا يرى لوحة المسؤول:** راجع قيمة `profiles.role` وتأكد أنها `ADMIN` للـ UUID الصحيح، ثم سجّل الخروج والدخول من جديد.

**لا تظهر مهام:** أنشئ أسبوعًا من لوحة المسؤول، ثم أضف مهامًا وحدد حساب المستفيد الذي ستُسند إليه. كل مستخدم يرى مهامه المخصصة فقط.

**تعذّر رفع التسجيل أو المرفق:** افتح Console في المتصفح وتحقق من اسم الـ bucket وPolicies؛ تأكد كذلك من حد الحجم ونوع MIME. يجب أن تستخدم الواجهة HTTPS أو localhost للميكروفون.

## ملاحظة بشأن Keep-Alive

سياسة Supabase الحالية توضّح أن مشاريع الخطة المجانية منخفضة النشاط قد تُوقَف تلقائيًا بعد فترة تقارب أسبوعًا، وأن عددًا قليلًا من الطلبات قد يساعد لكنه **ليس ضمانًا**. ملف `ops/keep_alive.example.yml` مثال اختياري لطلب فحص بسيط فقط، وليس حيلة مضمونة لتجاوز سياسة الاستضافة. اتبع تنبيهات Supabase ولوحة المشروع، واستعد لإعادة تشغيل المشروع يدويًا إذا أُوقف.
